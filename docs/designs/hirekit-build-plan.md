## Problem Statement
Ship HireKit as specified in PRD.md and Design.md: an evidence-backed, anonymized resume screener where humans decide. The PRD is complete on scope. This session settled what to build first, what the demo is, and which claims the docs can honestly make.

## What Makes This Cool
- Every score comes with a quote that code has checked against the resume, or an explicit "no evidence found".
- The model never sees identity signals, and a name-swap eval is meant to prove it.
- Demo goal: **the full pipeline in one take** (upload, anonymize, score, rank, override, interview kit, comparison).

## Constraints
- Model: `claude-haiku-4-5` via OpenRouter, `max_tokens` 1500, hard USD 8 spend cap (PRD G-1 to G-4).
- CI makes zero live calls; recorded responses only (G-6, G-7).
- Synthetic data only: 40 resumes, 2 roles, 20 name-swap pairs.
- Repo is empty. No stack is chosen in the PRD yet.

## Premises
Agreed in session, restated from the PRD:
1. Anonymization removes the **named identity signals** (name, gender, age, religion, location and their indirect carriers). It does not remove proxy leakage from schools, clubs, gendered wording or career gaps. State this as a known limit everywhere the fairness claim appears.
2. The demo runs from recorded responses (a "tape") with a budget-guarded live button, so it cannot exhaust the USD 8 cap mid-take.
3. The 40-resume agreement eval is a **consistency check**, not a quality measure. Resumes, labels and scorer are all Claude-family, and research shows LLMs favour AI-written text. Label it that way in the eval report, and add 10 to 15 hand-written or hand-labelled resumes if time allows.
4. A verified quote proves the text exists in the resume, not that it supports the score. The evidence block copy must not imply otherwise.

## Approaches Considered
- **A: Vertical slice** (steps 1 to 6 real, kit and feedback shown as recorded screens). Rejected: partly fakes the full-pipeline demo.
- **B: Full build order** (steps 1 to 9 as written). Rejected: largest surface, and a late anonymizer problem forces rework across the UI.

## Recommended Approach
**C: Engine first, UI second.** Build PRD steps 2, 3 and 5 as a library plus CLI first: gateway with budget cap and replay, anonymizer, scoring with quote verification. Get the anonymizer tests, quote tests, and both evals green in CI from recordings. Then build the UI (steps 1, 4, 6, 7, 8) over that engine. The demo plays a recorded pipeline tape end to end.
Why: the fairness claim and the budget cap are the two things that can sink the project, and both are provable before any screen exists.

## Open Questions
- Stack and hosting are unchosen (PRD gives none). Decide before step 1.
- PRD open questions 1 to 6 still stand. Two affect the demo: whether the ranked list shows names or IDs (Design.md recommends IDs) and whether interviewers see model scores before their own.
- Tape format: is the recorded pipeline the same replay store the tests use (recommended), or a separate demo fixture?
- Is a dark theme in scope for launch (Design.md open question 4)?

## Success Criteria
- Anonymizer suite 100% pass, including the hard cases in PRD 5.3.
- Name-swap eval: 20 of 20 within 1 point, run with names swapped before anonymization.
- Agreement eval reported as a consistency check, target 80% within 1 point, baseline to confirm.
- 100% of scores show a verified quote or "no evidence found".
- 0 live calls in CI; total spend at or below USD 8.
- The full pipeline demo runs start to finish from the tape without a live call.

## Distribution Plan
Web app. Nothing in the docs says how a demo audience reaches it. Decide one of: local run with a documented `make demo`, or a single hosted instance serving the tape. CI: run tests and both evals from recordings on every push.

## Next Steps
1. Choose the stack and record it in a one-page ADR.
2. Gateway: token cap, per-call log, USD 8 cutoff, replay keyed by request hash, refusal of non-anonymized input, with tests (PRD G-1 to G-9).
3. Anonymizer with the six-field suite and the hard cases.
4. Scoring with strict schema, quote verification, and the "no evidence found" cap (S-1 to S-5).
5. Seed data and record both evals once, deliberately, within budget.
6. Put the recorded pipeline behind a CLI, then build UI steps in PRD order (1, 4, 6, 7, 8) using the Design.md tokens.
7. Record the demo tape and add the budget-guarded live button last.

- You planned "Swap names before anonymization so the test actually exercises the pipeline" and flagged your own eval labels as model-generated. You were already distrusting your own tests.
