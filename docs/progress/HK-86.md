## Decisions
- Palette supersedes "reading room"; primary oklch(0.5 0.22 275) light, oklch(0.74 0.14 275) dark.
- Serif only for wordmark, h1 and evidence quotes; h2 and h3 use the sans.
- Content width is max-w-7xl (1280px); an arbitrary 1440 value would break the no-arbitrary-values rule.
- Font packages pinned to exact 5.3.0.
- Next-up is a primary button only for another step and when the screen has no primary of its own; on its own step it is text.
- Current step is a span with aria-current=step (TanStack Link forces aria-current=page).
- Review candidates links to the candidates page until stage 3 builds review mode.
- Review mode is wide-only (matchMedia, no layout in tests: jsdom defaults to the narrow list); the same list component links to the page below lg.
- Selection lives in the URL (replace for j/k, push for a click); ticks for compare stay local state.
- Compare in the tray is the one primary button on the candidates screen.
- Interviewer "submitted" state lives in the page (hook-level onSuccess), so it survives the form remounting read-only and does not exist on a revisit.
- Progress and submit both need score and comment (API rule), so "scored" means both.
- Compare has no totals or stage because the API returns none (N-W54).
- Dashboard counts use the first ranked page (100) per role because no summary endpoint exists; the page says so.
- Sidebar cookie: the generated sidebar writes `sidebar_state` on toggle but never reads it, so every load opens on desktop.
- Header stays 3.5rem and now sticks on every width, so review-rail and top offsets are unchanged (N-W48, N-W57).
- Stage 6: the resume scrolls with `region.scrollTo` (via `revealIn`), not `scrollIntoView` on the mark, because scrollIntoView would also move the page. The test mocks `scrollTo`.
- Stage 6: the interviewer form leads and the kit follows; scrolling the kit alone does not move the form (one direction avoids feedback loops).
- Stage 6: the compare page reads the first candidate for the role id (the comparison returns none), so the role name and back link appear after one extra request.
- Stage 6: the resume stays sticky only while its grid row lasts (the scores column), then scrolls away with it.
- Stage 7: the draft lives in component state (no draft endpoint), the flow opens on the first incomplete criterion (which also serves My candidates), and the recruiter scores section keeps useScrollSpy and SectionNav.
- Stage 7: no form element on the feedback flow, so Enter in a radio or the comment can never submit; the submit is a button on the review step.
